# Execution-Upgrade Spec (agentic-execution SOTA + product audits)

## Shared execution engine
"Converge BOTH products on a single three-layer substrate already present in both monorepos — do NOT invent new infra. (1) ORCHESTRATION = packages/central-intelligence kernel as the canonical Supervisor: effort-scaled lead agent (1 / 2-4 / 10+ subagents by query complexity, Anthropic orchestrator-worker pattern), with the kernel's confidence/judge/drift/policy/uncertainty rails ALWAYS run on the answer (no stamping). (2) PARALLEL/SWARM = packages/agent-orchestrator (swarm.ts / crew.ts / supervisor.ts / group-chat.ts — fully built, orphan in both repos, verified present): the single primitive for fan-out subagent teams, debate panels, and VP sub-MD dispatch via Promise.allSettled + state-reducer merge (LangGraph Send-style map-reduce). The multi-LLM synthesizer is the canonical parallel-LLM MoA, triggered by a shared stakes->requireSynthesis policy. (3) DURABILITY = packages/workflow-engine with Drizzle-backed Run/RunEvent/AuditChain/Approval repositories + the central-intelligence Inngest durable executor (checkpointed step.run, deterministic idempotency) for any multi-step / money / compliance / scheduled-wake / mission flow, with Sagas + compensating actions on the money path (preserving double-entry immutability via LedgerService.post). Cross-cutting, written ONCE: one AG-UI-style SSE event protocol (RUN/TEXT/TOOL/STATE typed events) for real streaming + HITL interrupt() gates on HIGH-risk policy prefixes and money/regulator actions; one token-aware budget governor (TPM + cost ceilings) to kill retry-loops; one LLM-as-judge + trajectory eval harness. Net: the subagent-executor, durable repos, synthesizer wiring, real streaming, and DAG scheduler are implemented against this substrate and consumed by both Borjie (mining) and BossNyumba (real-estate), which differ only in personas/tools/domain ports."

## Verdict
"Both products have world-class execution capability BUILT but DISCONNECTED — the audits are accurate (verified in source): the real swarm runtime (agent-orchestrator swarm/crew/supervisor/group-chat), multi-LLM synthesizer, durable Inngest executor, debate engine, and long-horizon mission engine all exist yet sit orphaned, while the live user path is a single-threaded ReAct/persona loop with fake streaming, no parallel agents, no durable resume, and answers that bypass the post-LLM rails. CRITICAL BLOCKERS (fix first, both repos): the md_subagent_runs team-dispatch dead-ends at 'pending' with no executor, mid-turn spawn_sub_md is a no-op ack, and durable workflow/wake state is in-memory (lost on restart, breaking the append-only audit-chain SOC2 claim). Highest-leverage move is convergence: wire the existing agent-orchestrator swarm + workflow-engine Drizzle repos + Inngest executor + synthesizer ONCE as the shared substrate, then route the canonical brain (kernel.thinkStream) into the real chat surfaces with real streaming and the rails re-enabled. Borjie is slightly ahead (orchestrator default + real parallel research engine); BossNyumba's worst risk is two divergent brain stacks where the weaker sequential one serves owners. Sequencing for Wave-2/3: (P0) unblock the dead-end executors + land durable repos; (P1) wire synthesizer/requireSynthesis + real streaming + re-run the rails; (P2) parallelize VP/junior fan-out as a DAG + add HITL gates + token-aware budgets + the eval harness. Effort is mostly WIRING, not greenfield — the superpowers are already coded."
