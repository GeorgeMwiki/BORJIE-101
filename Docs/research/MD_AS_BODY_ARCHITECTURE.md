# MD-as-Body Architecture (capstone) — the MD IS the OS, the project is its body

Source: md-embodied-os-sota workflow (cited dossiers in this dir).

## thesis
Mr. Mwikila (the MD) is not a chatbot inside Borjie — he IS the operating system, and the entire codebase (every app, portal, surface, service, package of Borjie AND BossNyumba) is his BODY. This is the literal realization of the Karpathy "LLM-as-kernel" / AIOS / AgentOS thesis, and the codebase is already ~85% there. The seven AIOS kernel organs map one-to-one onto shipped Borjie packages: LLM-core+scheduler = `central-intelligence` orchestrator (`main-loop.ts`, `anthropic-router.ts`, `sub-mds/registry.ts`); context-manager = `orchestrator/checkpoint.ts` + `context-budget.ts`; memory-manager = `memory-v2`/`cognitive-memory`/`persistent-memory`; storage = `database` (Postgres+RLS+pgvector) + `knowledge-graph`; tool-manager = `mcp`/`mcp-server` + `tool-dispatcher.ts`; access-manager = `policy-gate.ts`/`inviolable.ts`/`four-eye-approval.ts`/`killswitch.ts`/RLS. `agentic-os` (brain-first-gateway, capability-registry, living-kg, observation-loop, constitutional-preflight, trust-calibration) is already the explicit embodied-OS composition root. The four returns of self-modeling (Premakumar/Lipson: compression, prediction, anomaly-detection, planning) become how the MD behaves like an OS rather than an app: he holds a LIVE body schema of his own morphology (180+ packages, ~26 services, 9+9 apps), PERCEIVES across every surface, ACTS by growing/moving/rewiring surfaces, and (governed) REDESIGNS himself — every body-level change routed through the same `composeWithRail` monotone controller so "rail-gate always wins" extends to self-modification for free. The thesis is not aspirational: the spine (`autonomy-governance/decision/*`), the body-node table (`capability-catalogue` with hash-chain), the generative actuators (`portal-genui`/`genui`/`dynamic-sections`/`tab-as-loop`), the syscall layer (`mcp`), the state bus (`blackboard-sota`), and the fitness gate (`ui-evolution-worker`) all exist today. The work is to DERIVE the body schema (kill static `BRAIN_MODULES`), unify the actuators behind one syscall, and add the meta-rail. The destination is Nadella's phase-three: the agent OUTSIDE the apps, orchestrating the entire mining-estate operating fabric — while every competitor is still bolting a chat panel onto one SaaS screen.

## bodyModel
The MD's body schema is a LIVE, DERIVED, persisted self-model — never hand-authored (Anthropic introspection research: do not introspect from weights; ground self-knowledge in an external inspectable artifact). It is a single `system-graph` materialized as a Neo4j-style layered KG over the existing substrates (the Digital-Twins-as-self-models blueprint, PMC12365160):

LAYER 0 = Borjie/BN-the-OS (the self). LAYER 1 = sub-MDs/juniors (`central-intelligence/kernel/sub-mds/registry.ts` + the 50+ `ai-copilot` juniors). LAYERS 2-4 = surfaces -> screens -> capabilities -> data-flows. Digital threads = the existing hash-chained audit trail.

NODE TYPES (extend `org-graph/types.ts` EDGE_TYPES, which today only has lease/property edges): `surface` (the 4 Borjie apps + 9 BN apps + 2 portals), `screen`/`tab`, `service`, `package`, `capability`, `schema/table`, `mcp-server`, `junior`. EDGE TYPES to add: `renders_on`, `depends_on`, `flows_data_to`, `governed_by`, `measured_by`, `mirrors` (Borjie<->BN parity edges — the registry already says it "mirrors the BN sub-MD registry").

DERIVATION (ScaleMCP + UI-Evol: schema must be derived not authored, kept in sync by listChanged-style invalidation): a CI + runtime pass walks route manifests (`*.hono.ts`), screen registries (`dynamic-sections/registry`, `owner-os-tabs/registry.ts`), package exports, Drizzle schemas (`database/schemas/index.ts`), the MCP discovery output (`mcp/discovery`), and the `capability-catalogue` registry, then regenerates the system-graph. A `listChanged` invalidation fires on deploy/migration/flag-flip — killing the static-inventory drift that `self-awareness.ts`'s hand-written `BRAIN_MODULES` list suffers today (it lists 27 modules; the repo has 180+ packages).

NODE STATE (the proprioception/health layer — Topology-Aware AI-SRE, proven in production): each node carries live health from `observability`/OTel/Sentry + the `capability-catalogue` measurement axes (competence/calibration/utility per 7/28/91-day window, computed from OBSERVED outcomes per Ackerman — not verbal self-report). So the MD answers "what can I do where, and how good am I at it" by reading his declarative body (the imperative->declarative OS-interface spec, arXiv 2510.04607): "I can do offtake settlement, competence 0.91/28d, calibration error 0.04, renders on owner-web Royalties tab, governed by four-eye." A 500-ing route or a sub-threshold capability is an INJURED LIMB (Lipson damage-detection) the MD routes around and flags.

RENDERING (MemGPT paging — the schema is hundreds of nodes): keep a compressed organ-map self-summary resident in core context (the evolution of `renderModuleInventoryBlock`), and page in detail via a `query_body_schema()` tool on demand. The Free-Energy/active-inference loop (Friston): divergence between the body schema and ground truth (actual route table, capability health, deploy state) is PREDICTION ERROR, reconciled on the `reflexion` sleep/consolidation cycle (`sleep-pass-orchestrator` service) — every drift triggers a model update or raises an incident. The body GROWS (Voyager): when a capability or tab is tenant-authored (`capability-catalogue` already supports `tenant_authored` provenance + draft->shadow->live), the new limb auto-registers and becomes discoverable.

## selfRedesign
The MD reshapes his own body at runtime across three governed layers (Malleable Software: "a malleable agent doesn't treat its own architecture as sacred, but as clay reshaped by feedback" — surfaces, flows, prompts, tool-defs all live as inspectable/versioned DATA over Postgres+RLS+audit-chain, so reshaping is a data patch not a release):

L1 — MOVE / REORDER existing surfaces (adaptive UI; the behavioural counterpart to genUI). The MD reorganizes the body around what each owner/manager/buyer actually does: `dynamic-sections` (evaluate.ts/filter.ts) reorders sections; signal moves from static rules to LEARNED intent (role x season x deadline x usage — surface FX-treasury near a USD-cliff). Redeploy-free because it's data: Airbnb Ghost Platform's sections-by-ID + named-placements pattern (move/reorder without resending data) + server-defined actions through a central handler (rewire what a button does / what screen follows submit). `tab-need-detector`'s scoring-matrix is the seed.

L2 — ADD surfaces AND capabilities without redeploy. New SURFACE: the MD emits a UI DATA document (A2UI flat-list+ID-references for incremental patches: "add column"/"move section" instead of regenerating whole docs); `genui` client owns renderers; the escape hatch for novel surfaces the 35-primitive catalog can't express is an MCP-Apps-style sandboxed-iframe lane (CSP-isolated, still no service redeploy). New CAPABILITY (Agent Skills as folder+SKILL.md, three-level progressive disclosure; Voyager self-authored composable skills keyed by when-to-use): the MD codifies a recurring pattern (royalty reconciliation) into a vetted Borjie Skill dropped into the registry the dispatcher reads at runtime — `skill-library`/`voyager-library` + `capability-catalogue`'s draft->shadow->live lifecycle + `tenant_authored` provenance + the self-verification gate before a skill enters the library, with evidence-required + audit-chain + policy-gate intact.

L3 — GOVERNED SELF-MODIFICATION (the bounded, safe slice — Gödel-Agent's own failure taxonomy is the verdict: complexity ceiling, self-comprehension breakdown, recursive-module-damage; so NEVER an unsupervised live monkey-patch of the `central-intelligence` kernel). The SAFE form is ADAS/Meta-Agent-Search: the MD doesn't rewrite the kernel, he COMPOSES new sub-agent graphs and control flows from vetted juniors (metallurgy, FX-treasury, compliance, safety) for novel mining situations — a search over compositions of TRUSTED parts. `self-extension.ts` already implements exactly this (detectRecurringGap -> proposeNewSubMd -> owner four-eye approval -> compileAndDeploySubMd -> sovereign-action-ledger; new sub-MDs land in `riskTier: 'read'` by default, never auto-deploy destructive). Promotion uses the Darwin-Gödel-Machine empirical-fitness + archive-lineage pattern: `ui-evolution-worker` (aggregator/approval/decisions/audit) promotes a generated surface/skill to live ONLY after it beats the incumbent on adoption/completion/error/approval — redeploy-free CI for behaviour, with `mutation-authority` (recipe registry, proposal builder, double-verify guard, rollback, audit-chain link) as the executor that refuses to run without the two-operator gate. The Auditor/defection/sycophancy probes (`metacognition/defection-probe.ts`, the `defection-probe.yml`/`sycophancy-probe.yml` CI gates) guard the self-redesign loop too.

## governance
Every body-level change (prompt / memory / tool / UI / code / self-model) routes through the SAME continuous controller already shipped in `autonomy-governance/src/decision/`, just entering at a higher consequence tier and defaulting to `staged` reversibility. `decide-autonomy.ts` fuses confidence x consequence x reversibility x mandate x situation; `compose-with-rail.ts` combines it with the rail stack via a MONOTONE max over `auto < gate < four_eyes` so a rail can only ESCALATE — RAIL-GATE ALWAYS WINS, proven by construction. Adding a meta-rail term as one more monotone input cannot weaken that proof, so the guarantee extends to self-modification for free.

THREE PERMISSION TIERS (capability-based least privilege; Oso/AgentGuardian): INSTRUCTED (owner asks — normal gating), PERMITTED-not-instructed (the MD hands a sub-MD a provably narrower slice of its own self-mod rights via attenuable capability tokens/macaroons; scopes for which organs may be self-edited are learned from observed need — `org-scope`/`authz-policy`/`tenant-isolation-guard`), GATED (consequence/situation forces a human). The mandate ladder (observer->operator in `types.ts`) is the RSP-v3 ratchet: deeper self-edit rights demand a higher safety-case bar.

THE META-RAIL — the one organ the surgeon cannot operate on: a net-new deterministic, no-LLM, fail-closed `checkBodyChangeInviolable` (sibling to `inviolable.ts`) forbidding any body-change that edits/disables/routes-around the rails, shortens an audit/provenance path, raises its own mandate ceiling or lowers its confidence floor, or fails a cryptographic registration-integrity check; threaded into `composeWithRail` as one more monotone input. This is lexicographic corrigibility (Provably Corrigible Agents: deference > switch-access > truthfulness > low-impact > reward) at the decision level — a change trading any higher head for reward is forbidden by construction. It maps to the existing `driftTowardSovereign` (four_eyes-escalating) and `irreversibilityBudgetExhausted` (per-window body-change budget — Misevolution: a reversible-looking change can be the first step of irreversible drift).

REVERSIBLE: shadow -> canary (1->10->50->100% with eval/latency/cost/error gates) -> burn-rate-SLO auto-rollback to the ARCHIVED parent body (DGM archive-fork-validate-promote; `shadow-mode`/`rollout`/`cutover-gate`/SLO-auto-rollback all shipped — the gap is wiring them to the body-change path; `isolated-vm`/`sandbox` is sandbox-before-deploy). PROVABLE: VeriGuard dual-stage (offline formal verification proves generated code preserves rails BEFORE execution + constant-time online monitoring — explicitly for self-modifying systems where guardrails might be circumvented through code-gen); AgentSpec trigger->predicate->enforcement DSL generalizes the regex rails into a checkable spec. ACCOUNTABLE: every body-change is sovereign-class with a named four-eye approver + hash-chained `sovereign_action_ledger` entry + a re-emitted Sigstore-signed AI-BOM (`ai-bom-attest.yml`) — the antidote to the 2025-AI-Agent-Index "accountability diffusion" finding and the enforcement of the meta-rail's no-audit-shortening clause.

## Verdict
BUILD IT — the architecture is sound, SOTA-grounded, and already ~85% present in the codebase; this is a unification + derivation + meta-rail effort, not a greenfield build. The MD-as-body thesis is the correct capstone: it unifies the orchestration brain (`central-intelligence`), autonomy (`autonomy-governance` — the proven monotone spine), skills/workflows (`skill-library`/`self-extension.ts`/`capability-catalogue`), situational awareness (`world-model`/`belief-engine`/`agentic-os/observation-loop`), dynamic UI (`portal-genui`/`genui`/`dynamic-sections`/`tab-as-loop` — flagship already wired), and voice (`voice-bridge`/`voice-agent`) under one coherent OS model where the entire project is the MD's body. THREE non-negotiables for safety: (1) the body schema MUST be DERIVED and persisted, never hand-authored from weights (Anthropic introspection + the static `BRAIN_MODULES` drift is the cautionary case in-repo); (2) the META-RAIL is the load-bearing safety innovation — it is what lets the owner say "reshape everything" while keeping the nerve that keeps the body correctable forever, and it extends the existing monotone proof for free; (3) L3 self-modification stays ADAS-style composition of trusted parts + DGM empirical-fitness promotion, NEVER an unsupervised monkey-patch of the kernel (Gödel-Agent's own failure taxonomy is the verdict). The moat: Borjie/BN reaches Nadella's phase-three (agent OUTSIDE the apps, orchestrating the whole operating fabric, owning and rewriting its own surfaces — what Astra cannot do) deliberately, while every competitor is still at phase one. Sequence the 14 lanes spine-first: system-graph derivation + health attachment + meta-rail (the body must know itself and be uneditable-at-the-nerve before it acts on itself), then unified body-change syscall + reversible/provable wiring, then the actuation/ambient/MCP-span lanes.
