### 1.1 SENSES — always-on perception (the bottom of the Mind, the input to everything)
The estate is sensed continuously, not polled per request. The **Estate Radar** fuses Endsley L1 (perceive) → L2 (comprehend a cross-domain "danger shape" via CEP) → L3 (project a near-future trajectory with **lead-time-to-act**), ranks signals by **Bayesian surprise** (`KL(posterior‖prior)`) on one **prediction-error bus** (replacing literal `ratio>1.5` thresholds), and catches slow regime drift with BOCPD/CUSUM changepoints. An **event-stream subscriber** consumes `event_outbox` + ledger/licence/FX/KYC + the standing **regulator feed**. Senses write *Comprehension* and *Projection* objects into the resident Situational Model — they never recompute cold. *(MD-kernel §5.1; Data-Foundation Pillar A; gaps EA-07, KI-16/17, COG-15.)*

### 1.2 MIND — the resident EstateMind heartbeat (INV-D, the meta-controller)
The single structural deficiency the whole corpus identifies is the **trigger model**: today the cognitive cycle fires per HTTP request (`think(req)`) and per cron tick, with no long-lived mind holding state between turns. The fix is the **resident `EstateMind`** — a per-tenant, durable, recursively-viable mind running **two concurrent loops over one shared state**:
- **Slow Loop — `EstateMind.tick()`**: `PERCEIVE → ORIENT → ORGANIZE → CREATE → EXECUTE-to-closure → LEARN`, on a perpetual heartbeat, writing the situational model every tick, formulating its **own goals** (the loops nobody asked about) via a GDA discrepancy organ, and driving open loops to confirmed closure. Each `flow_id` is a durable workflow that survives restart.
- **Persistent Current Situational Model**: a per-entity activation field (recency×freq + spreading), an open-loop registry, standing-concern status, and a **Global-Workspace single broadcast** ("the one thing I'd worry about as your MD right now") — read first on every consequential turn, never lost.
- **Standing-drives / Motivational Subsystem**: a durable, learnable registry of **maintenance/interest goals** (cash never breaks, the licence never lapses, grade never silently drifts, margin is protected, the workforce is safe). These **generate goals** that seed the analytical question-tree, the proactive surfacing, and the org-design loop.
- **Fast Loop — `think(req)`**: a chat turn *reads* the live situational model (never recomputes cold) → recognition-primed, instant, warm, **honestly calibrated** answer. The owner experiences instant chat; the estate experiences a tireless resident MD.

Generality is **structural, not aspirational**: ORIENT does **Recognition-Primed Decision** (Klein RPD) + Case-Based retrieval over a typed `SituationPrototype` library (rows authored from the corpus, never `switch` statements). Recognised → run the veteran's primed playbook (cheap, the 80%); no-match → drop to deliberate search (LATS/debate, the 20%) **and flag the resolution for distillation** into a new prototype (the library grows itself). The mind is structured as a **recursive Viable System** (Beer S1–S5 + algedonic channel): the estate is a *fractal of MDs* — estate-MD → site-MD → function-MD — each viable over its slice, the residual escalating up one **unified algedonic spine**; the **3–4 homeostat** engages the owner (S5) *only on break*, curing approval-fatigue. The decisive external result the whole Mind leans on: **metacognition must be external architecture, not a prompt** (Mirror: an architectural control loop cuts confident-failure 76%; giving the model a calibration score changes nothing). INV-D's structured backend loop *is* that scaffold. *(MD_COGNITIVE_KERNEL_ARCHITECTURE entire; gaps COG-15/03/01/02, EA-07.)*

### 1.4 FABRIC — the operational closed-loop nervous system (drive to confirmed closure)
A **consequential event** is any state that, unattended, costs money, a licence, a person's safety, or a relationship. The fabric turns each into a **complete, uniform, durable loop**: `DETECT (outbox-sourced) → REGISTER a loop → SCHEDULE a durable LADDER (data-defined offsets, LLM-authored within rails) → FIRE once cluster-wide (the durable engine makes fire-once free) → ROUTE on the recipient's preferred channel (+ cross-channel fallback + delivery/read receipts written back) → ACT (a junior drafts the remediation, not a nag) → ESCALATE up the live org/rota graph on inaction → FOLLOW-THROUGH a tracked task → CONFIRM closure from the SOURCE OF TRUTH (ledger posting / licence row), never from a message read → AUDIT every step (hash-chained, at-least-once) → LEARN (self-tune ladder/channel/timing per recipient as an APPEND)`. The closure invariant is **Perceptual-Control-Theory semantic completion**: a goal is complete *iff the controlled perception matches its reference*, verified by a per-goal **grounded verifier** that re-queries real state; recovery is **strictly leveled (L1 retry → L2 patch → L3 replan)**, never abandon-on-first-failure. *No 2026 vendor closes this whole loop* — the integration over our RLS-Postgres + hash-chain invariants is the moat. *(OPERATIONAL_CLOSED_LOOP_FABRIC entire; MD-kernel §5.2; gaps RSS-01/02/06, EA-07, EXEC-saga.)*

### 1.5 HANDS — the reversibility-typed actuator port + portal-driver (INV-F)
The Mind produces *intents*; the Hands turn intent into **proven, completed real-world work** — default **DO, not suggest**. The keystone is a **uniform actuator PORT** sitting above adapters, with five SOTA properties **baked into the type** so the rails fall out of the type system, not out of code review:
- **`reversibility` ∈ {reversible | compensable | irreversible}** → the autonomy gate enforces INV-F **mechanically**: `irreversible ⇒ requiresApproval ⇒ four-eye before confirm`. Money/licence/deletion are HITL **by construction**.
- **`idempotencyKey`** (deterministic `(tenant, plan_id, step_index)`) → at-most-once *effect* end-to-end; at-least-once delivery + idempotent effect = exactly-once-effect.
- **`dryRun`/`preview`** (mandatory, side-effect-free) → the structural answer to "DO not suggest, but never surprise": the debate/LATS loop runs on previews, the human approves the preview, `confirm` executes *exactly what was previewed* — this IS the PREPARE step.
- **`confirm`** (the single committing verb; PAYMENTS actuators confirm *through* `LedgerService.post()` — the money invariant satisfied by definition).
- **`compensate`** (reversible→undo; compensable→offsetting forward action; irreversible→refuse + raise manual review) → saga rollback uniform across every category.

A **portal-driver** is a first-class transport: BRELA/Tume-ya-Madini/TRA lack clean APIs, so the brain sees only the *capability* (`mining.renew_licence`) and never knows whether a robot fills the cadastre form or a REST call fires — the day the regulator ships an API, the transport swaps and every dependent junior is untouched. Sensitive actions follow **PREPARE → REVIEW+PERMISSION → EXECUTE-or-HANDOFF**: the MD does the full labour autonomously, asks "prepared and ready — shall I execute, or will you?", and **tracks to confirmed closure even when the owner takes the wheel**. The **action-orchestrator** compiles each `action_plan` into one durable saga whose steps are the actuators and whose sleeps are the await-windows, with a **completion certificate** binding every receipt into the audit chain — court/regulator-grade proof no advisory product can produce. *(THE_HANDS entire; gaps RSS-01/16/21/23, EXEC-saga, the actuator-port + saga-executor joints.)*

## 2. HOW THE LAYERS INTERLOCK — one trip around the living loop

The eight systems are not a static stack; they are **one continuous loop** at a single altitude that the organism runs forever. Read it as a sentence — this is the literal control flow that makes Mr. Mwikila alive:

```
 standing-drives (MIND) generate a goal ──▶ SENSES surface a surprising signal against a standing concern
   │                                                            │
   ▼                                                            ▼
 the MIND ORIENTS via RPD prototypes (recognised → playbook; novel → LATS + distil a new prototype)
   │
   ▼
 the MIND ORGANIZES: rank by consequence × reversibility; decide autonomous-vs-gated; if a tool/organ/
   surface/type is MISSING ──▶ CONSTRUCTION synthesizes it as a reversible data-patch through the META-RAIL
   │                                                            │ (proposal → approve/refine → reversible commit → audit)
   ▼                                                            ▼

   │
   ▼
 the HANDS execute the prepared package: dryRun → preview → (HITL on irreversible: prepare→ask→execute-or-handoff)
   → confirm via the actuator → capture the receipt → compensate-on-failure
   │
   ▼
 the FACE shows the work live (plan card, junior rail, reasoning fold, evidence chips, inline lens) and surfaces
   the proposal / the prepared package; the owner approves / refines / takes the wheel — bidirectionally
   │
   ▼
 the DATA FOUNDATION captures EVERYTHING losslessly (outbox co-commit), confirms closure from the source-of-truth
   row (never a message read), updates the situational model, writes bi-temporal facts + lineage
   │
   ▼

   new prototype/skill, GEPA-optimise prompts on the replay buffer, roll back any organ that didn't earn its keep
   │
   └──────────────────────── the loop closes; the situational model is warmer; the next turn is faster ──────────┘
```

**The named handshakes (where two systems weld):**
- **MIND → CONSTRUCTION:** CREATE fires *mid-cycle on impasse* (Soar immediacy / Ashby `V(D)>V(C)` / HTN no-method), not on a daily cron; the resolution is **chunked** back into the skill library so the impasse never recurs.
- **CONSTRUCTION → everything:** every synthesized organ lands through the **modality arbiter** (the 7-way head: ANSWER/SKILL/WORKFLOW/LOOP/AGENT/ACTUATE/run_modality) — the single seat captured skills, discovered workflows, the loop-runner, and the actuators all sit in. Without it they have nowhere to land.
- **CONSTRUCTION → FABRIC:** a self-built loop-type is a `loop_registry` row; the fabric's `draft_action` rung invokes the relevant junior; the fabric's closure plane confirms from the source-of-truth row.
- **FABRIC → HANDS:** a `draft_action` rung that touches the real world calls an actuator through the port; the autonomy gate decides auto-vs-HITL per step from `reversibility × cost × posture × rails`.
- **HANDS → DATA FOUNDATION:** every actuator receipt co-commits an `EstateEvent`; money closure is observed **only** from the ledger; the completion certificate binds receipts into the hash chain.
- **DATA FOUNDATION → FACE:** `metric == lens` — every analytical answer is a faithful, interactive inline lens; the Faithfulness Gate guarantees the chart cannot lie; the situational model feeds the Fast Loop so chat is warm.
- **FACE → MIND:** a barge-in or a slider-drag is a *turn* that re-plans remaining steps in place; the visible-work layer is the calibrated window into the resident mind.
- **everything → META-RAIL:** every construction is a proposal; **everything → INVIOLABLE FLOOR:** money/licence/deletion always hit the policy-gate; **everything → DATA FOUNDATION:** nothing is ever lost.

The interlock is what makes the difference between "a chatbot that sometimes does things" and "a self-constructing organizational brain": the same loop senses, decides, builds the missing organ, drives it to closure, acts, shows the work, captures it, and learns — perpetually, behind one chat, on the immovable rails.
