Source: orchestration-intelligence-sota workflow (cited dossiers in this dir). Drives the build.

## Orchestration architecture
THE ARBITER-FIRST ORCHESTRATION BRAIN. Today the only live arbiter is the anthropic-router (anthropic-router.ts:215-261), which collapses every turn to `tool_call | respond_to_owner | final` — `spawn_sub_md` is reachable only when the LLM hand-emits it, and skill/workflow/loop are never reachable. The Decision ADT (decision.ts:135-160) already declares the richer shape; the gap is a MODALITY ARBITER that runs BEFORE router.call in main-loop.ts:716. Build it as 5 concrete, reusable layers.

(1) IDENTIFY — Modality Arbiter (NEW: kernel/orchestrator/modality-arbiter.ts). A cheap first-pass classifier (reuse the on-device MiniLM router + brain-llm-router cascade) that maps every inbound request/event to one of FIVE modalities, applying Anthropic's complexity-ladder rule "start simplest, climb only when simpler fails": ANSWER (one-shot RAG — 'what's my royalty due?'); SKILL (a verified entry already in skill_registry that matches by embedding ≥ DEFAULT_SKILL_MAX_DISTANCE — retrieve-and-run via the EXISTING wired skill-retriever, kernel.ts:1046); WORKFLOW (a known deterministic multi-step flow — match against ai-copilot/workflow-registry WORKFLOWS, e.g. process_royalty_payment, onboard_new_site); LOOP (open-ended iteration — 'figure out why production dropped at Site B' — runs the EXISTING-but-ORPHAN loop-runner.runLoop with quality-gates); AGENT/SWARM (decompose + spawn_sub_md fan-out via the WIRED md-subagent-executor.runSubagentTeam). The arbiter emits a 7th Decision variant `run_modality` consumed by dispatch. Effort-scaling spawn rules baked in (Anthropic multi-agent): 1 agent/3-10 tool calls for facts, 2-4 sub-MDs for comparisons, 10+ only for deep research — gating against over-spend.

(2) FORMULATE — when modality=AGENT/SWARM the arbiter writes each sub-MD's mandate using the EXISTING SubMdSpawn contract (decision.ts:55-101: persona, prompt, tools whitelist, disallowedTools, model class, effort, permissionMode, budget envelope, riskTier ceiling). This IS the OpenAI-Agents-SDK 'instructions+tools+handoffs+guardrails+output-type' contract — already present, just unfed by the arbiter. When modality=WORKFLOW, formulate = bind WORKFLOWS step targets to real tools. For deterministic flows use Plan-and-Execute / LLMCompiler DAG: commit the plan once (existing dispatchPlanner picks ToT for low/medium, LATS for high/critical stakes — planner-dispatcher.ts:107) and run independent steps (licence-validity, tax-status, permit-check) in parallel.

(3) DISPATCH — Supervisor by default (Mr. Mwikila over domain juniors: metallurgy, compliance, fx-treasury, safety, sales-offtake, esg — matches Borjie's central auditable governance). Direct HANDOFF for conversational flows (buyer-KYC → sales-offtake) via spawn_sub_md with `background:false` inline isolation. SWARM reserved for the runSubagentTeam parallel fan-out (md-subagent-executor.ts:103-145, race-safe claim, Promise.allSettled, evidence-required). Wire the real sub-MD run (sub-md-spawn-handler.runChild:344, already calling orchestrator.think with tier transitivity) as the AGENT executor.

(4) COMPLETE + VERIFY — verify final STATE not steps (frontier consensus + Borjie's mandatory Auditor): for each modality emit a verifier check — WORKFLOW step done = its tool effect satisfied (ledger posting balanced, licence row updated); LOOP done = loop-quality-gates pass (groundedness+calibration+brand+authority+budget, the EXISTING Layer-4 combinator); AGENT done = runSubagentTeam evidence chain non-empty (md-subagent-executor.ts:232 already enforces). Add semantic-entropy abstention on HIGH-risk (sovereign/kill_switch/four_eye) recommendations — multi-sample, cluster by meaning, escalate if entropy high rather than bluff.

(5) REPAIR + CAPTURE — REPAIR: on a precondition failure preserve the executed prefix and jump to the unaffected state (HTN plan-repair, faster than replan-from-scratch); add a re-planner node driven by failure signals; write a Reflexion natural-language reflection into the EXISTING durable cognitive memory. CAPTURE: connect the DARK half of the skill-library — on a self-verified novel success, the post-turn/consolidation pass calls compileSkill + autoSuggestSkill (skill-compiler.ts, currently no runtime caller outside tests) to extract a parameterised skill, human-review-gate it, and promote into skill_registry so the next matching turn resolves to modality=SKILL (Voyager describe→embed→store→retrieve→compose). DELETE the dead standalone @borjie/skill-library and @borjie/tab-as-loop packages — the kernel skill-library + loop-runner are the canonical implementations.

## Autonomy-gating model
- **defaultBehavior**: USER-GATED until explicitly set to AUTO (HITL / L1-Operator). The existing primitives are global-master + per-tool-tier + per-stakes (autonomy-policy.service.ts:177-197) + four-eye on medium/high/critical (four-eye-approval.ts) + per-turn permission-mode (main-loop.ts:725-769). The structural gap: gating is keyed on toolName/stakes under ONE GLOBAL switch (autonomousModeEnabled), NOT on flow identity. Default-deny the dangerous surface BY RISK CLASS not every action (Anthropic's own telemetry: per-action prompting → users rubber-stamp ~93%, oversight becomes theater; gate-by-risk-class cut prompts 84%). Money-path (LedgerService), licence actions, deletions, external comms are NEVER auto-eligible — they always hit literal HIGH-risk policy rules.
- **onFlowCreation**: A ONE-TIME auto-vs-gated confirmation at flow-creation, with the flow's track-record shown at the moment of asking (trust-calibration — prevents overtrust from a blind 'yes'). NEW: add a flow-keyed autonomy column. Today autonomy_policies + tenant_autonomy_caps are keyed on tenant_id only (autonomy-caps.schema.ts:37) and there is NO workflow_id/flow_id/tab_id autonomy row and NO creation-time confirm (grep confirm-creat/per-flow = none). Build `flow_autonomy_prefs(tenant_id, flow_id, posture[gated|auto-bounded|auto-monitored], risk_ceiling, amount_threshold, created_by, promoted_at)`. New flow created GATED by default; the creation UI surfaces the LangGraph interrupt_on-style map (read=AUTO, write/execute=gate) and the MD picks per-flow. Sticky decision = one policy row (the OpenAI-SDK always_approve primitive = 'this flow is now AUTO').
- **graduation**: EARNED / trust-based promotion (progressive autonomy — never default to L5). A flow created GATED accrues a track record in the Generative-Agents-style memory stream (clean runs, escalations, error trend, false-escalation rate). After N clean runs below an error threshold (FAQ heuristic 100-500 instances scaled by stakes; far fewer for low-risk estate flows) Borjie SUGGESTS flipping to AUTO with the evidence shown — Reflexion drives the readiness signal (a flow that reflects on failures, drops its error rate, and stops escalating is demonstrably ready). A promoted AUTO flow becomes a verified entry in the skill library (Voyager: named, verified, reusable). DEMOTION is automatic: NIST-style interrupt conditions / risk tripwires auto-demote an AUTO flow back to GATED on rising error / anomaly / low confidence / cap-slowdown. Money/licence/deletion flows are NEVER auto-promotable regardless of track record.
- **enforcement**: DEFENCE-IN-DEPTH at three seams, capability-layer beneath all of them. (1) autonomy-governance: evaluateAutonomyCap (cap-evaluator) runs BEFORE four-eye/sovereign — wire the kernel hook that the package docstring flags as a follow-up (index.ts:18 'kernel-side hook ... is a follow-up'); enforce maxMutationsPerDay (schema present autonomy-caps.schema.ts:41 but only the COST dimension is live via orchestrator-bindings.ts:403). (2) workflow-engine: the change-governance state-machine (start→propose→review→approve→commit, hash-chained audit per transition) is where a WORKFLOW-modality flow's human-approval gate lives — read flow_autonomy_prefs to decide whether the approval step is skipped (AUTO) or blocks (GATED). (3) policy-gate / permission-mode in main-loop.ts:760 — the per-turn arbiter reads flow_autonomy_prefs and sets permissionMode per-flow instead of globally. CAPABILITIES (the layer beneath autonomy): each junior gets a scoped capability set (tool+param restrictions, read/write/execute scope, TTL); AUTO promotion widens the autonomy POLICY ONLY, never the capability set — so an AUTO flow still cannot exceed granted authority and the LedgerService money-path + RLS hard rules hold. EU-AI-Act Art.14 floor retained in AUTO: stop-button, override/reverse any output, anomaly detection, two-person dual-control on money movement + licence actions.
- **targetAreas**: packages/autonomy-governance (cap-evaluator kernel hook — wire the follow-up; mutation-count enforcement), packages/database (NEW flow_autonomy_prefs schema + service; extend autonomy-caps with flow_id; migration), packages/central-intelligence/src/kernel/orchestrator (permission-mode + modality-arbiter read flow prefs per-turn), packages/workflow-engine (approval-step skip/block driven by flow posture), packages/central-intelligence/src/kernel/policy-gate.ts + four-eye-approval.ts (per-flow not global), packages/central-intelligence/src/kernel/skill-library (promoted AUTO flow → verified skill), packages/capability-catalogue (scoped capability sets per junior)

## Situational awareness
UNIFIED ESTATE-STATE MODEL — today self-awareness.ts is persona-drift + capability inventory (NOT situational state), and the real fragments (world-model forecasts, agency goal-tracker pending/running/done/blocked, stall-detector active→stalled, briefing daily digest) are DISJOINT with no standing model and no blind-spots structure (grep blind-spot/knownUnknown = only doc-comments). Build ONE queryable per-tenant artifact the orchestrator reads FIRST every turn (Anthropic long-running-agent re-orientation ritual: read state → highest-priority undone item → verify-before-work; the AI audit chain is the immutable git-log analogue).

THE SIX-FACET MODEL (NEW: kernel/awareness/estate-situation.ts), externalized outside the context window and loaded just-in-time (Anthropic context-engineering — survives resets, no context rot): HAPPENED (episodic memory — past decision trajectories, completed flows, posted ledger entries, from the cognitive-memory + audit chain); DOING (agency goal-tracker `running` goals + in-flight sub-MDs + loop-runner active cycles); TODO (goal-tracker `pending` + `blocked` + stall-detector active→stalled self-heal proposals); FUTURE (world-model forecasts — licence renewals, royalty filing windows, bid expiries, seasonal cycles, FX thresholds — plus a Voyager automatic-curriculum 'what could matter next' planner); BLIND-SPOTS (NEW first-class known-unknowns map: facts the brain lacks but a decision needs — drives clarify/abstain via semantic-entropy + LangGraph interrupt rather than bluffing); CAVEATS (confidence band + uncertainty-policy attached to every HIGH-stakes output; abstain→escalate on high semantic entropy, complementing the existing intent-verification + sycophancy gates).

CONSTRUCTION: facets are RETRIEVED + SYNTHESIZED each turn using the Generative-Agents recipe — scored retrieval (recency exp-decay 0.995 + LLM importance 1-10 + cosine relevance), with a reflection pass firing at cumulative importance ~150 that synthesizes piles of documents into 'what now needs doing' (evidence-cited, satisfying Borjie's mandatory evidence_id rule). A BDI commitment governor persists an intention while its preconditions hold — the antidote to thrashing when new docs arrive mid-task; re-deliberate only on genuine context change (HTN plan-repair, not replan-from-scratch).

DATA ROUTING (captured doc → where/why/follow-up). The doc-ingest router is REAL (document-analysis decideRouting:136, ROUTING_MATRIX, HITL-gated below threshold → ModuleUpdateProposal create_lease/post_receipt/archive_id) and follow-up reasoning is REAL (user-followup priority scorer + quiet-hours + channel dispatchers; followup-cron pulls flagged/deadline/dormancy). The TWO MISSING JOINS: (a) routed data with a deadline is never turned into a scheduled follow-up candidate — add the doc-to-followup insert path so a ModuleUpdateProposal carrying a date emits a follow-up candidate (CoALA: fact→semantic, event→episodic, how-to→procedural; a dated obligation→FUTURE facet + follow-up scheduler). (b) proactive-triggers-worker is library-complete but UNDEPLOYED (no Dockerfile/entrypoint, only ref is a k8s TODO) — ship the container/cron host so runScheduledPasses + the 3 scheduled passes actually fire, and the Letta sleep-time consolidation pass (existing reflexion-sleep-canary) pre-computes the morning briefing during idle. PROACTIVITY is gated (PROBE: SOTA caps at 40% end-to-end, 73.8% of failures are root-cause identification) — spend the most reasoning budget + evidence on root-cause synthesis, and surface proactive output as inform/draft (not auto-act) until confidence×reversibility clears the bar. Every facet step is OTel-instrumented (GenAI agent observability — step-level tracing is the structural blind-spot detector; divergence/tool-errors/missed-sources become visible via decision-trace).

## Verdict
BUILDABLE NOW — the hard primitives already exist; the missing piece is a head, not a heart. Borjie has the Decision ADT (7-variant-ready), a wired sub-MD team executor + real spawn_sub_md child runner, stakes-aware ToT/LATS planning, a wired skill-RETRIEVE half, a real doc-ingest router, real follow-up reasoning, autonomy caps/SLO/canary/rollback substrate, and four real situational fragments. What is missing is (1) a MODALITY ARBITER that runs before the LLM router so skill/workflow/loop/agent become reachable instead of collapsing to tool_call — this is the single highest-leverage build; (2) FLOW-KEYED autonomy with a creation-time confirm + earned promotion, replacing the global master switch — small schema + wiring, large behavioral payoff; (3) a UNIFIED six-facet estate-situation model the orchestrator reads first each turn, unifying the disjoint fragments and adding the never-built blind-spots layer. Three orphans (loop-runner, dynamic-recipe-authoring, skill-capture half) and one undeployed worker (proactive-triggers) just need wiring/shipping; two dead packages (@borjie/skill-library, @borjie/tab-as-loop) should be deleted. Sequence: arbiter + loop wiring first (turns the lights on), then flow-keyed autonomy + cap hook (makes AUTO safe-by-construction), then the situation model (makes the MD always know happened/doing/todo/future/blind-spots/caveats). Money/licence/deletion flows remain dual-control HITL forever; everything else earns its way up the L1→L4 ladder. This is frontier-grade and faithful to Borjie's hard rules — no LedgerService bypass, RLS intact, evidence-required, hash-chained audit, fail-closed kill-switch.
